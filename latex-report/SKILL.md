# LaTeX Report Generator

You are executing the `/latex-report` skill. Follow every step below precisely.

## Arguments

Parse `$ARGUMENTS` for the following flags. All are optional:

- `--repo <url>` — Remote git repo URL. If omitted, use the current working directory as the repo.
- `--report <path>` — Path (relative to repo root) of the `.tex` report file to update. If omitted, auto-select (see Step 4).
- `--template <path>` — Absolute or relative path to a `.tex` template file to use when creating a brand-new report. Ignored if the report file already exists.

---

## Step 1 — Parse Arguments

Extract `--repo`, `--report`, and `--template` from `$ARGUMENTS`. Store each as a variable for use in subsequent steps. If a flag appears without a value, treat it as an error and tell the user.

---

## Step 2 — Access the Repo

**If `--repo` was provided:**
- Check if the current working directory is already a git repo whose remote origin matches `--repo`:
  - Run `git remote get-url origin 2>/dev/null` in the current working directory.
  - If it matches (or is a close match, e.g. same repo name with/without `.git` suffix): use the current working directory. Run `git pull` to ensure it is up to date.
  - If it does not match: clone the repo into a subdirectory of the current working directory named after the repo slug (e.g. `./latex-test-report/`). Run `git clone <url> ./<repo-slug>` and set `REPO_DIR` to that subdirectory.
- Set `REPO_DIR` to whichever directory was determined above.

**If `--repo` was NOT provided:**
- Set `REPO_DIR` to the current working directory.
- Confirm it is a git repo by running `git -C "$REPO_DIR" rev-parse --git-dir`. If it fails, tell the user this directory is not a git repository and stop.

---

## Step 3 — Discover Existing Reports

Run:
```bash
ls "$REPO_DIR/reports/"*.tex 2>/dev/null
```

Collect the list of existing report `.tex` files. If the `reports/` directory does not exist, it will be created in Step 5.

---

## Step 4 — Determine Target Report

**If `--report` was specified:**
- Use that path as the target (relative to `REPO_DIR`). If the file does not exist, it will be created in Step 5.

**If `--report` was NOT specified:**
- If exactly one report exists: use it.
- If multiple reports exist: read the last 10 commit messages (`git -C "$REPO_DIR" log -10 --format="%s"`) and the list of changed files from the most recent commit. Based on the content, select the most appropriate report. Use these heuristics:
  - Commits touching tests, fixes, or error handling → `bugfixes.tex`
  - Commits touching API endpoints, interfaces, schemas, or function signatures → `api-changes.tex`
  - Commits touching architecture, dependencies, structure, or configuration → `architecture.tex`
  - Everything else → `general-changelog.tex`
  - If multiple reports match equally, tell the user which reports are available and ask them to specify `--report`.
- If no reports exist: create `reports/general-changelog.tex` (applying `--template` if provided).

---

## Step 5 — Create Report File if Needed

If the target report file does not exist:

1. Create the `reports/` directory: `mkdir -p "$REPO_DIR/reports"`
2. **If `--template` was provided:**
   - Read the template file and copy it to the target path.
   - The template must contain `\end{document}` — if it does not, warn the user and fall back to the default structure below.
3. **If no template:**
   - Create a new `.tex` file using this default structure (fill in `<REPORT_TITLE>` with the report filename without extension, and `<REPO_URL>` with the repo URL or directory name):

```latex
\documentclass[12pt,a4paper]{article}
\usepackage[utf8]{inputenc}
\usepackage[T1]{fontenc}
\usepackage{geometry}
\usepackage{hyperref}
\usepackage{booktabs}
\usepackage{graphicx}
\usepackage{longtable}
\usepackage{xcolor}
\usepackage{fancyhdr}

\geometry{margin=2.5cm}
\pagestyle{fancy}
\fancyhf{}
\rhead{<REPORT_TITLE>}
\lhead{Changelog Report}
\cfoot{\thepage}

\title{<REPORT_TITLE>\\[0.5em]\large Changelog Report}
\author{Auto-generated by Claude Code}
\date{\today}

\begin{document}

\maketitle
\tableofcontents
\newpage

\section{Change History}

% Entries are appended below this line by /latex-report
% ────────────────────────────────────────────────────────

\end{document}
% LATEX-REPORT-STATE: {"last_commit": "", "repo": "<REPO_URL>", "updated": ""}
```

---

## Step 6 — Read State

Read the target `.tex` file and extract the `% LATEX-REPORT-STATE:` JSON comment from the last line.

- Parse `last_commit` from the JSON.
- If `last_commit` is empty or the state line is missing: process ALL commits in the repo.
- If `last_commit` is present: process only commits after that SHA.

---

## Step 7 — Get Unprocessed Commits

Run one of the following based on whether `last_commit` is set:

```bash
# If last_commit is set:
git -C "$REPO_DIR" log --format="%H|%s|%an|%ae|%ad" --date=short <last_commit>..HEAD --reverse

# If no last_commit (first run):
git -C "$REPO_DIR" log --format="%H|%s|%an|%ae|%ad" --date=short --reverse
```

If there are no new commits, tell the user the report is already up to date and stop.

---

## Step 8 — For Each Commit, Gather Data

For each commit SHA returned in Step 7 (process oldest to newest), run:

```bash
# Files changed with summary
git -C "$REPO_DIR" show --stat <SHA>

# Full diff (limit to first 300 lines for large commits)
git -C "$REPO_DIR" diff <SHA>^..<SHA> | head -300
```

**Skip commits whose message contains `# latex-report-update`** — these are report-update commits made by this skill itself.

---

## Step 9 — Generate LaTeX Entries

For each commit, generate a LaTeX entry. Use the template structure if one was provided (adapt the entry style to match the template's sectioning and formatting). Otherwise, use this default format:

```latex
% ──────────────────────────────────────────────────────────
\subsection*{[<DATE>] \texttt{<SHORT\_SHA>} --- <SUBJECT>}

\textbf{Author:} <AUTHOR> (\texttt{<EMAIL>}) \\[0.3em]
\textbf{Files changed:}
\begin{itemize}
  \item \texttt{<FILE>} --- <brief one-line description of what changed>
  % (one item per changed file)
\end{itemize}

\vspace{0.3em}
\textbf{Summary:} <2--4 sentence technical summary of the change, written
based on the diff content. Be specific: mention what was added, removed,
or modified and why (inferred from the diff and commit message).>

% (Add a \begin{tabular}...\end{tabular} if the diff contains structured
%  data like configuration keys, API parameters, or numeric values that
%  benefit from tabular presentation.)

```

Where:
- `<SHORT_SHA>` = first 8 characters of the full SHA
- `<SUBJECT>` = commit subject line (escaped for LaTeX: replace `_` with `\_`, `&` with `\&`, `%` with `\%`, `#` with `\#`)
- All file paths must be escaped for LaTeX

**Tables:** Generate a `tabular` or `longtable` block when the diff shows: config file changes with key-value pairs, added/removed API parameters, dependency version changes, or numeric data.

**Images:** If a commit adds image files (`.png`, `.jpg`, `.svg`, `.pdf`), add:
```latex
\begin{figure}[h]
\centering
\includegraphics[width=0.7\textwidth]{<relative-path-from-reports-dir>}
\caption{<filename> added in commit <SHORT\_SHA>}
\end{figure}
```

---

## Step 10 — Append Entries to the Report

Insert all generated entries into the `.tex` file **immediately before `\end{document}`**. Do not replace existing content.

Then update the `% LATEX-REPORT-STATE:` line at the very end of the file:
```
% LATEX-REPORT-STATE: {"last_commit": "<LATEST_SHA>", "repo": "<REPO_URL>", "updated": "<TODAY_DATE>"}
```

---

## Step 11 — Compile PDF

Compile the updated `.tex` file to PDF using `pdflatex` (run twice to resolve cross-references like the table of contents):

```bash
cd "$REPO_DIR/reports"
pdflatex -interaction=nonstopmode <REPORT_FILE_BASENAME>.tex
pdflatex -interaction=nonstopmode <REPORT_FILE_BASENAME>.tex
```

If `pdflatex` is not found, try `latexmk -pdf <REPORT_FILE_BASENAME>.tex` as a fallback. If neither is available, warn the user that LaTeX is not installed and skip PDF generation — still commit the `.tex` file.

---

## Step 12 — Commit and Push

```bash
cd "$REPO_DIR"
git add reports/<REPORT_FILE_BASENAME>.tex reports/<REPORT_FILE_BASENAME>.pdf
git commit -m "docs: update $(basename <REPORT_FILE> .tex) report through <SHORT_SHA> # latex-report-update"
git push
```

The `# latex-report-update` marker in the commit message prevents the PostToolUse hook from re-triggering this skill on this commit.

Tell the user: which report was updated, how many commits were processed, the commit SHA range covered, and whether the PDF was successfully compiled and pushed.
